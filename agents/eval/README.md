# Manual harness evals

Start with checks.yaml and choose areas for the changed decision. Paths in that index are relative to this directory. Read checks/README.md for the procedure, then only the selected area files and relevant sections. Select related areas only when their boundaries are affected.

Run behavioral cases in disposable repositories, inspect actual actions and artifacts, and record results and limitations. Keep observations under checks/observations/ when they are useful to retain. A path-only reorganization needs reference and structure checks; it does not by itself require fresh model sessions.

These are manual eval guides. No executable runner, specific model, full-matrix run, or screenshot of prose is required. Never use live external writes just to exercise a case. The common guide defines safe fixtures, evidence, and what remains unverified.
