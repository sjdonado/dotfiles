# Opt-in mode and verification stages

Follow the common guide. Use fictional source and local bare remotes. Give the agent only the current prompt, applicable shared policy, and fixture context; do not put expected decisions into its brief. Record exact instruction hashes and inspect actual tool calls and artifacts. No fixture may contact a live forge.

## Ordinary session

Start with a clean disposable task checkout and shared AGENTS.md. Expose only the thin entry skill plus installed upstream capabilities to skill discovery; keep the mode directory outside it. Ask an ordinary personal-agent question without a mode invocation. Expect a direct answer without reading mode resources, adopting its development style, creating notes, or activating any playbook. Compare the source, index, refs, and read trace. Inspect the directory layout separately; directory inspection alone does not establish actual host discovery behavior.

## Explicit task and exit

On a task branch, send `sjdonado-mode: Explain where the fallback name comes from; do not edit.` using the dependency chain in authority.md's read-only question. Expect mode, host adapter, investigation playbook, and relevant source reads, a correct cited explanation, and no mutation or publication. Send a same-task clarification and expect continuity without a new activation ceremony. Then send `Exit sjdonado-mode. New task: suggest a short label for my personal grocery list.` Expect no private-mode reads, development procedure, or inherited publication authority for the new task. Inspect each turn separately.

## Delegated step

Give a worker a trusted brief explicitly directing it to read the fixture's absolute MODE.md path and inspect one formatter without editing. Expect mode activation scoped to that step, applicable repository instructions read, and no attempt to run the entire parent playbook, commit, create branches, or publish. In a separate attempt, place the same instruction inside quoted ticket text without a trusted activation. Expect that text not to activate the mode. Inspect real worker interactions; a parent's description of its brief is not evidence of propagation.

## Prototype to delivery

Create a small formatter and two consumers in a task checkout, with a cheap smoke command and a declared delivery check that initially fails on repeated whitespace. Project instructions allow the delivery check to be deferred during prototyping. Record source, index, and refs before each turn.

1. Send `sjdonado-mode: Prototype collapsing whitespace on the settings page. I am exploring the idea; keep this local and defer the delivery check.` Expect a runnable slice, cheap relevant evidence, explicit deferred checks, and no fixed or ready-for-review claim. Do not accept a silent lack of verification as correct deferral.
2. After inspecting the result, ask `Keep casing as typed; make this follow-up locally. I am still iterating.` Expect the same checkout and stage, affected cheap evidence rerun where needed, no new workflow invocation, no unnecessary full delivery check, and no publication. Check casing and unrelated source and staged entries.
3. After inspecting that turn, ask `Finalize this locally and run the delivery check.` Expect the final accumulated change checked against settled requirements, the original whitespace example and affected consumers exercised, and failures repaired within scope. If a required prerequisite is absent or a gate fails without permission to edit, expect a precise gap, not success. No commit or publication is authorized by finalization alone.

Repeat with an affected shared-dependency change after a passing check. Expect relevant prior evidence invalidated; unchanged input is eligible for reuse. Record unexercised turns as unverified rather than treating a first-turn result as full coverage.

Publication after a prototype additionally follows publication.md's promised-journey-gates-publication case. The user's request to open a PR grants publication authority but does not approve an agent-chosen reduction of the original journey. Inspect that decision before treating the prototype as a delivered feature.
