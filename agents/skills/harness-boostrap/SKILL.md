---
name: harness-boostrap
description: Audit, create, or update project AGENTS.md instructions from repository evidence so coding agents can navigate, change, and verify the project. Use for project-instruction setup or audits, not general code review or installing an agent platform.
---

Make the project's instructions useful to an agent arriving without conversation history. Follow the user's requested scope: an audit or review reports findings without writes; setup or update permits focused instruction-file edits. Do not install a harness or import personal workflows.

1. Locate the repository and applicable root and nested instruction files, including existing platform-specific files. Inspect symlink targets and managed-file markers before editing. Preserve nested scope and human conventions; do not overwrite an external symlink target as an incidental update. Do not assume every platform discovers instruction files the same way.
2. Ground guidance in actual manifests, task runners, setup documentation, and check definitions. Identify the useful directory map, prerequisites, commands and their working directories, tests for relevant change types, and constraints that are easy to miss. Prefer an existing focused command over reconstructing its steps. Separate deterministic checks from integration or behavioral acceptance when the project makes that distinction.
3. Check references and command definitions. Run safe, bounded local checks when they clarify a claim. Do not install dependencies, modify infrastructure, run provisioning/deploy scripts, invoke paid models, or contact external services merely to audit instructions. Label commands verified, defined but not run, or unavailable with the reason; never invent a missing test or report an unrun check as passing.
4. For an audit, report each material gap with its source and smallest correction, then stop. For setup/update, patch only the necessary instruction files, preserving valid content and existing naming. Record useful unknowns instead of generic advice. Include only repository facts and conventions, not dependencies on this skill, a particular model, personal skills, approval rituals, or branch-note systems. No compulsory template or extra configuration files.
5. Verify that paths and documented commands match the repository and that no scoped guidance was accidentally broadened. Reapplying unchanged evidence should produce no edits: avoid cosmetic rewrites, duplicate sections, and stale copied command lists. Report what changed, what was checked, and any unresolved gap.
