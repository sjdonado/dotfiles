# Implementation

1. Ground the requested outcome in the relevant code and repository instructions. Recover settled requirements from the current task. For a bug, reproduce the failure on its actual surface or with a faithful executable trigger; record the failing observation. Trace its mechanism before fixing it. If the surface is unavailable, name the missing prerequisite and avoid a runtime-fix claim.
2. Choose the shape before writing logic. Read the applicable principles in MODE.md. For a nontrivial ownership or interface change, compare at least two viable structures, using independent design exploration when available. Resolve a genuine product fork with the user; routine design choices do not require approval. For a refactor, pin the existing behavior before moving structure and verify equivalence afterward.
3. Split substantial work by disjoint ownership and name shared state before fan-out. Use a scoped implementation delegate when this preserves a separate lead for design and review. A quick local fix can stay with one owner. Delegate briefs carry MODE.md and repository instruction paths, requirements, allowed actions, and success evidence. A child forbidden to delegate owns its assigned diff directly.
4. Implement only the agreed behavior. Reproduce and eliminate the root cause rather than adding speculative guards. Preserve unrelated edits and staged work. Read skills/worktree/SKILL.md if separate isolation is needed; never change the user's chosen checkout merely because feedback arrived.
5. Apply the delivery stage in skills/principle-prove-it-works/SKILL.md to the final accumulated change. For a bug, repeat the original failing observation; for shared behavior, check affected consumers and relevant failure paths. Run required project checks. Fix failures caused by the task and distinguish unrelated failures with evidence.
6. Use skills/agent-review/SKILL.md for a requested review or concrete unresolved correctness, security, compatibility, or contested-design concern. State the question and authoritative requirements. Adjudicate findings against evidence; fix real defects, explain rejected findings, and ask only for a product or authority decision. Rerun evidence affected by fixes.
7. Finish at the agreed outcome. Leave local work uncommitted unless commits were authorized. For PR delivery, read skills/open-pr/SKILL.md and carry the promised behaviors and their evidence into its publication gate. A request to publish does not replace those behaviors with the current diff's narrower capabilities. Continue through routine failures; report a real blocker with the exact unimplemented or unverified behavior rather than declaring completion.
