# Prototype and iteration

1. Name the question the prototype should answer and the smallest journey the owner can try. Keep experimental assumptions separate from settled product requirements.
2. Read the applicable principles in MODE.md, then build a runnable slice. Reuse the current checkout and components. Delegate substantial independent work when useful; a small adjustment needs no design panel or new task note.
3. Apply the prototype stage in skills/principle-prove-it-works/SKILL.md. Run the cheapest check that establishes the slice can be tried. Capture the behavior being explored when useful. Do not claim production correctness from fixtures or a demo.
4. Incorporate feedback in the same task. Recheck affected behavior and required project gates at their prescribed time; defer expensive delivery checks until the design settles unless the change introduces a concrete immediate risk. Record which claims remain unsupported rather than rerunning unchanged checks after each tweak.
5. Hand back how to try it, what it demonstrates, and deferred checks. When the user asks to finalize or deliver, switch to the implementation playbook on the accumulated diff and complete its verification stage. A prototype never silently graduates to publication.
