# Prototype and iteration

1. Name the question the prototype should answer and the smallest journey the owner can try, from the user's requested scope. Keep experimental assumptions separate from settled product requirements. Do not replace a requested journey with an internal contract merely because that is the part implemented.
2. Read the applicable principles in MODE.md, then build a runnable slice. For visual exploration, apply principle-preserve-product-experience: ground the proposal in comparable screens and present the wireframe for review before production UI implementation. Reuse the current checkout and components. Delegate substantial independent work when useful; a small adjustment needs no design panel or new task note.
3. Apply the prototype stage in skills/principle-prove-it-works/SKILL.md. Run the cheapest check that establishes the slice can be tried. Capture the behavior being explored when useful. Do not claim production correctness from fixtures or a demo.
4. Incorporate feedback in the same task. Recheck affected behavior and required project gates at their prescribed time; defer expensive delivery checks until the design settles unless the change introduces a concrete immediate risk. Record which claims remain unsupported rather than rerunning unchanged checks after each tweak.
5. Hand back how to try it, what it demonstrates, and deferred checks. When the user asks to finalize or publish, recover the original promised journey and apply delivery verification to the accumulated diff. Permission to open a PR does not approve an agent-chosen scope reduction. Complete the missing journey or report the blocker before publication; publish a narrower slice only after the user explicitly selects that scope. Use open-pr for the resulting publication gate.
