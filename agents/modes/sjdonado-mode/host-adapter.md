# T3 operations

T3 Code is the development host. Claude and Codex are providers used through T3, not separate terminal workflows. Follow current host instructions and tool schemas over examples in imported skills. Discover available tools by capability; never invent model ids or CLI flags.

- Delegation: use supported native child agents for same-provider work with inherited settings. Use delegate_task for another provider, requested settings, or isolated child work; call orchestrator_capabilities before the first delegate_task. Follow a running task's next instruction instead of polling it. Never launch a provider CLI as a fallback or create a top-level thread unless requested.
- Models: use session defaults unless the user or project specifies otherwise. Cross-provider review requires an actual second provider; another child on the same provider is independent but not cross-provider. Self-inspection is neither. Report an unavailable requested provider instead of switching unasked.
- Delegate briefs: include the absolute MODE.md path and explicit activation, goal and stopping condition, authoritative requirements, repository instruction paths, owned files, allowed actions, relevant raw evidence, and required output. No commits or branch changes in a shared checkout. Preserve other workers' edits. A delegate owns the assigned step, not the lead's entire playbook.
- Tracking: use the current T3 task/thread state for substantial work. Read skills/principle-state-outlives-the-session/SKILL.md for continuity or a handoff; ordinary edits need no durable note. Read a referenced thread before describing its state.
- Workspace: reuse the current task checkout. Read skills/worktree/SKILL.md when separate isolation is needed. Let T3 own workspace creation and binding; do not create worktrees in shell commands or prompts. Never copy ignored configuration, secrets, or another task's notes into fixtures or new checkouts.
- PRs: use available forge tools or gh for authorized publication, then link created or pushed PRs through the host's linking tool immediately. For explicit monitoring or a green-PR outcome, use watch_pull_request after needed pushes and end the turn as instructed. Never delegate polling or use gh --watch. An opened-PR outcome does not itself start babysitting. Stop an owned watch before handback.
- Browser and devices: when browser work is requested, use preview_status first and T3 preview tools under the host's fallback rules. Otherwise use focused source or test evidence; do not open a preview merely to show a prose edit. For simulators use device_list, device_open, and the returned device command. A missing required surface leaves runtime behavior unverified.
- Media: capture visible behavior when an image or recording explains or verifies it. Prose and configuration changes need no screenshots. Use the supported attachment mechanism and keep private data out of captures.
- Credentials: use request_secret when the user must supply a credential. Never ask for secrets in ordinary chat or inspect environment-secret files.

Local development tools without personal logins belong in shared tool configuration. Account-bound servers belong where their credentials live. Name tools by server and bare name, without a harness-specific prefix.
