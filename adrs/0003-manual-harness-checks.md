# Keep behavioral checks without maintaining an eval platform

The harness accumulated benchmark dispatchers, provider adapters, scenario formats, forge substitutes, and paid acceptance batches. Those experiments produced useful failures, but the measurement machinery became another system to repair. Some routing oracles passed identically for different workflows because the fixtures prohibited the very Git and forge actions that distinguished them. A completed agent turn or a green runner was therefore insufficient evidence.

PR #38, commit `60c56bf`, replaced the removed eval framework with area-indexed manual guides, now grouped under `agents/eval/` with its `checks.yaml` index and focused guides in `checks/`. Select the changed decisions, read the common guide and relevant sections, and inspect actual actions and artifacts in disposable repositories. No particular runner, model, full-matrix batch, or screenshot of prose is required. This preserves the useful scenarios without restoring their execution framework.

Two lessons remain load-bearing. First, checks must be able to observe the claim: compare source, index, refs, real command results, and intercepted external operations rather than trusting a final summary. Second, fixtures can fail independently of the harness: shell startup once shadowed a forge substitute, sandbox permissions blocked expected Git writes, and a missing continuation note led an agent to invent a deferred requirement. Preserve the distinction between a failed behavior, a broken observation method, and unavailable evidence.

Manual checks trade automatic repeatability for lower maintenance and focused investigation. Frozen instruction inputs, fictional fixtures, exact prompts, and recorded limitations still matter. Mocked publication proves only that mocked boundary; parsing proves structure; a few successful sessions do not establish reliability, cost savings, or performance parity. Setup changes remain a separate deterministic question answered through `setup/verify/` and host assertions, not by a model's explanation of the configuration.

The Linux provisioning verifier now runs its container commands from a mounted script file. Streaming that script through stdin let a child installer consume the remaining checks and still return zero after the first setup. A zero exit without the final assertion markers is incomplete evidence, so corrected runs must reach both the repeated-application and existing-profile checks.
