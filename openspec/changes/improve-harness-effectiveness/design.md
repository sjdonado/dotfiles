## Goals / Non-Goals

Goals: lower the amount of interpretation required at transitions, preserve user decisions across sessions, and detect false completion with a small test surface.

The new harness-boostrap skill has a separate portability boundary: it produces repository facts and useful operating instructions for any capable coding agent. It must not export this harness's routing, approval process, branch-note format, model choices, or skill dependencies into other projects. This repository can document its own benchmark tools because they are actual project tools, not prerequisites imposed on other repositories.

Non-goals: a new tracking skill, hook framework, database, dispatcher, event log, model-specific prompt forks, rewriting all skills, or certifying every model. Keep the existing note format, branch identity, local ignore mechanism, and OpenSpec tasks as source of truth.

Audit/review requests inspect and report only; explicit setup/update requests permit a minimal patch. Resolve the repository root, existing root/nested agent instruction files and symlinks, authoritative manifests/task runners, setup documentation, and verification sources. 0b. **Discoverable verification, no false green.** Extend bench/measure with `verify --local` and `verify --behavior` as one command family, documented in root AGENTS.md and bench/README.md. Local mode executes the applicable deterministic checks, while behavioral mode evaluates the declared scenario matrix and exits nonzero for failure, missing required coverage, or exhausted budget. Local green alone must never be described as harness acceptance. Record per-scenario outcomes and exact input hashes so completed checks can be reused only for the same harness/skill/scenario/model configuration; rerun only invalidated results. Preserve a visible distinction between missing model access and a behavioral failure. Behavior mode's model calls and session budget must be explicit. A fresh yolo run resolves this entry point through its existing repository discovery rather than a new yolo-specific adapter.

The pre-existing changed instruction files should not grow in total word count: remove superseded or conflicting text to pay for concrete checkpoints. Measure the new optional skill and project-local instructions separately rather than pretending new capability is free or forcing deletions of necessary constraints.

## Self-grill

- Assumption: stronger wording guarantees adherence. Refuted by the existing attempt; wording is a hypothesis whose acceptance depends on actual scenario outcomes. If it still fails, do not keep appending instructions. Follow the existing rabbit-hole limits and bring back the smallest mechanical enforcement hypothesis as a separately scoped decision.
- Assumption: a missing note means the task is blocked. False when the contract remains available; explicitly test recovery and unrecoverable context separately.
- Assumption: passing tests means the intended task is done. Refuted by Luna's invented fallback; expectations must come from the preserved user contract and an independent oracle.
- Assumption: one compact model represents every model. Unsupported. Use a second available configuration, report limited coverage, and avoid universal claims.
- Assumption: more scenarios always improve confidence efficiently. Unsupported. Cover the observed transition failures and one read-only boundary; defer broader inputs such as images, tracker threads, semantic merges, and auth changes until a specific failure warrants a fixture.
- Assumption: a portable setup skill should install this harness. Rejected by the user's scope. Its output must stand on repository evidence alone, tested in a fixture without personal workflow dependencies.
- Assumption: a root AGENTS.md can promise a command before it exists. Rejected. Bootstrap with working checks first; wire the full behavioral entry point only once it is implemented, retaining pending acceptance in the interim.

## Risks / Trade-offs

- Model compliance remains probabilistic. Smoke failures block an effectiveness claim; a passing sample does not certify reliability.
- Local external-service substitutes can conceal integration errors. Label this coverage explicitly and retain normal PR checks in yolo.
- Stronger missing-contract handling can create excess questions. Require an artifact search before asking and use the recoverable-context case to catch unnecessary stops.
- Larger instruction payloads can undo efficiency benefits. Compare the exact changed files and remove duplication; do not optimize token counts by removing correctness constraints.
- The current runner is not hermetic. Retain CLI/settings metadata and prevent accidental prior-prompt access; no claims of strict model isolation.

## Migration Plan

Keep the current branch and note format. On approval, yolo first bootstraps root AGENTS.md using existing repository evidence, then builds harness-boostrap and applies its audit to that document, repairs the existing harness, and completes the benchmark entry point before final acceptance. This avoids requiring a not-yet-created skill or command to start implementation. Retain previous failed artifacts and validate before publishing. No state migration is required. Yolo owns the accumulated branch diff, preserves unrelated local edits, and never merges. Revert individual implementation commits if behavior regresses, preserving benchmark evidence. Main specs are synced only through land after merge.
