# Design

## Context

See proposal.md for motivation. Current provisioning, in the order a machine meets it:

- `macos.sh`: Xcode command line tools, Homebrew, `mise bootstrap` (formulas, casks, taps, `go install`), `mise install` (`[tools]`), `mise run pss-sync`, `agent-browser install`, BrowserRouter copy and `lsregister`, fish in /etc/shells and `chsh`, fish history relocation, the claude curl installer, `lib/links.sh` functions, Docker config, keyboard layouts copied into ~/Library/Keyboard Layouts, `.ssh/config`, duti, `macos/defaults.sh`, `macos/app-shortcuts.sh`, two launch agents rendered from templates, `.hushlogin`.
- `linux.sh`: apt base, `mise install`, pss-sync, agent-browser's Chrome (not on arm64), claude and herdr curl installers, PATH and git-identity blocks appended to ~/.profile, ~/.zshenv, ~/.bashrc and ~/.zshrc, the `exec fish` block for interactive shells, `lib/links.sh` functions.
- `lib/links.sh`: every link, plus generated state: `herdr integration install claude|opencode` (before the settings link), herdr plugin link and install with pinned refs, `bin/codex-config apply`, `bat cache --build`, pruning of links this repository no longer ships.
- `verify/linux` (Ubuntu container, `linux.sh --install` twice), `verify/macos` (throwaway HOME, `macos.sh --links-only` twice), `verify/macos-vm` (tart guest, full `macos.sh`).

Proto evidence (uncommitted on main): `flake.nix`, `flake.lock` (nixpkgs 8edc0c72e3, home-manager 92a0ed1be1), `nix/home.nix`, `verify/nix/linux.sh`. home-manager switched 12 tools and 4 live links twice in a `nixos/nix:2.28.3` container on aarch64, and the second switch kept generation 1.

Constraints: the repository lives at `~/.config/dotfiles` on both platforms. Flakes see only files git tracks, so new files must be staged before a build. Linux boxes include Coder workspaces, whose agent runs scripts through the POSIX login shell and which inject git identity variables.

## Goals / Non-Goals

**Goals:**

- One flake, two entry points (`darwin-rebuild switch --flake .` and `home-manager switch --flake .`), and one shared home module for what both platforms have.
- One upgrade command that is itself part of the flake (`nix run .#upgrade`), covering `flake.lock`.
- Verification on disposable machines for both platforms before the host changes.

**Non-Goals:**

- NixOS, or managing anything outside the user's account on Linux.
- Packaging GUI apps from nixpkgs on macOS (see decision 5).
- Changing what the tools do: configurations keep their content, only their provisioning moves.
- Secrets: .env files, SSH keys, and tool logins stay manual.

## Decisions

1. **Layout.** `flake.nix` at the root with outputs `darwinConfigurations.<hostname>`, `homeConfigurations.linux-aarch64` and `linux-x86_64`, and `apps.<system>.upgrade`. Modules under `nix/`: `home/common.nix` (packages and links for both platforms), `home/linux.nix` (shell files, zsh hand-off), `home/darwin.nix` (user-level macOS steps), `darwin/system.nix` (defaults, shells, Nix settings), `darwin/homebrew.nix` (brews, casks, App Store apps, taps). Rejected: one file per platform, because packages and links would be duplicated, which is how `lib/links.sh` came to exist.

2. **Installing Nix.** The Determinate Systems installer on both platforms, installing upstream Nix, with nix-darwin managing `nix.conf` on macOS. It survives macOS updates, which is the known weak point of the official installer, and uninstalls cleanly with `/nix/nix-installer uninstall`. Rejected: Determinate Nix (its own daemon conflicts with nix-darwin managing Nix, requiring `nix.enable = false`); the official installer (no uninstaller, breaks on macOS upgrades). Flip: the VM rehearsal shows the installer cannot install upstream Nix on macOS 27.

3. **User and host.** macOS: the darwin configuration is keyed by hostname and names the user explicitly. Linux: user and home come from the environment (`--impure`), as in the proto, because Coder workspaces and VMs use different user names. Rejected: one Linux configuration per user, which needs a repository edit per box.

4. **Package sources, in order:** nixpkgs (unstable, pinned) → a pinned upstream flake input for a tool nixpkgs lacks or lags on badly → a Homebrew formula from a pinned tap. From the availability check (`.agent/main.nix-map.tsv` in the proto, to be moved into the change): 93 of 96 formulas and all 17 mise tools come from nixpkgs, as do claude-code (unfree), herdr, air, bootdev-cli and goose. Three stay Homebrew formulas: `sjdonado/tap/browser-router`, `cliclick`, and `mole` (nixpkgs `mole` is an SSH tunnel tool, not the Mac cleaner). `openssl@3` maps to `openssl` and `openssl@4` to `openssl_4_0`. `allowUnfree` is set for claude-code and the unfree tools. Implementation found two tools that need the second source: OpenCode (nixpkgs carries v1, this setup runs v2) and Codex (nixpkgs compiles it, and Hydra's aarch64-linux builds stopped finishing after 0.157). Both are packaged in `nix/pkgs/` from the native binaries their npm packages publish, pinned by version and hash. Versions Homebrew kept off PATH because they share command names (jdk11, jdk17, llvm, openssl 4, zig 0.15) are linked under `~/.local/opt/`, and GNU tools that would shadow macOS ones keep Homebrew's names (`gsed`, `gawk`, `coreutils-prefixed`, `telnet` alone). The macOS formula set stays macOS-only, as before: Linux boxes get the shared tools, not the macOS toolchains. The `docker` formula (installed `link: false`) is not replaced: OrbStack supplies the client, and buildx and compose are linked into `~/.docker/cli-plugins`.

5. **GUI apps stay casks** on macOS, including the 15 that nixpkgs also packages. Casks install into /Applications as real bundles, which Launch Services, Spotlight and Raycast index; nixpkgs apps land under a Nix-managed directory as links or aliases, which is exactly the class of indexing problem met with the Safari web apps. The 11 hand-installed apps that have casks (cap, google-chrome, granola, imageoptim, libreoffice, linear-linear, orion, raycast, slack, whatsapp, zed) and the undeclared `codex` cask join the list. The 13 App Store apps go in `homebrew.masApps` by App Store ID. Rejected: nixpkgs apps through `mac-app-util` trampolines, an extra layer for no gain over casks.

6. **Homebrew under Nix.** nix-homebrew installs and owns Homebrew, adopting the existing `/opt/homebrew` (`autoMigrate`), with every tap a non-flake input (`mutableTaps = false`), so tap versions move only with `flake.lock`. nix-darwin's `homebrew` module applies the list with `onActivation.autoUpdate = false`, `upgrade = true` (to the pinned tap state) and `cleanup = "uninstall"`. Rejected: `cleanup = "zap"`, which also deletes app data; `cleanup = "none"`, which lets undeclared items persist. The first host switch runs with `cleanup = "none"` and a comparison before `uninstall` is enabled (migration step 4).

7. **Live links.** Every config link is `mkOutOfStoreSymlink` into `~/.config/dotfiles`, as in the proto, so edits apply without a switch and write-backs (nvim-pack-lock.json, opencode kv.json, pi settings.json) reach the tracked file. Each live link is declared with `force`, so the first switch replaces the links `lib/links.sh` made at the same paths without a collision error or a backup. Directory-level links stay where `lib/links.sh` uses them (nvim, agents/skills); per-file links stay where tools write their own files beside ours (~/.local/bin, herdr config, opencode plugins). home-manager's own link pruning replaces `prune_stale_links` for links it created; the one-time removal of links `lib/links.sh` made before the migration is a migration step, not permanent code.

8. **Setup steps as activation.** Each non-package step becomes a named home-manager activation entry after link generation, each wrapped so a failure prints the step name and continues: herdr integrations (claude before the settings link stays ordered by running it in a `writeBoundary`-stage entry that checks for the hook file first), herdr plugins with the pinned refs, `bin/codex-config apply`, `bat cache --build`, pss (its repository becomes a pinned non-flake input; the step runs `bun install` and links `pss` from that store path instead of cloning `main`), `agent-browser install` (its Chrome version is fixed by the pinned agent-browser package; skipped on Linux arm64 as today), Neovim plugin restore from the tracked lockfile, `.hushlogin`, keyboard layouts (copied, because macOS does not load layouts through symlinks), duti, BrowserRouter copy and `lsregister`, and the Caps Lock and Time Machine scripts. Launch agents become home-manager `launchd.agents` (labels `org.nix-community.home.*`; a step boots out and removes the old `com.local.*` agents); the Finder defaults become `system.defaults`. App shortcuts stay `macos/app-shortcuts.sh`, run as a step instead of `CustomUserPreferences`: Safari's domain fails without Full Disk Access, and in `CustomUserPreferences` that failure would stop the whole activation. The pss step is macOS-only, where `pi` is installed; on Linux the old `mise run pss-sync` failed for lack of `pi`.

9. **Superseded (2026-10-17): neovim is a plain editor.** The owner edits in Zed with T3 Code and keeps neovim only as git's editor, so `nix/home/common.nix` declares `neovim` alone; the language servers and formatters below, lazygit, tree-sitter, the `nvim/` link, the plugin-restore step and the upgrade's plugin update are commented out, ready to restore. Original decision: **Mason tools become Nix packages.** The 14 language servers and 7 formatters `nvim/init.lua` installs through Mason (astro-language-server, basedpyright, clangd, crystalline, css/eslint/json servers, gopls, golangci-lint-langserver, lua-language-server, svelte-language-server, tailwindcss-language-server, vtsls, yaml-language-server, black, gofumpt, goimports, isort, prettierd, ruff, stylua) move to `home.packages`, and mason.nvim and mason-tool-installer leave the config; servers resolve from PATH. Rejected: keeping Mason, which downloads binaries outside the declaration. Each package's nixpkgs name is checked with the same evaluation the availability check used before the config changes.

10. **Superseded with decision 9 while `nvim/` is not linked.** **Neovim plugins stay on vim.pack with the tracked lockfile.** The lockfile pins every plugin commit, so a switch restores exactly those; `nix run .#upgrade` runs the plugin update that rewrites the lockfile, beside `nix flake update`. Rejected: nixpkgs `vimPlugins`, a rewrite of the plugin setup for no change in pinning.

11. **Shell environment.** Linux: home-manager owns ~/.profile, ~/.bashrc, ~/.zshenv and ~/.zshrc (`programs.bash`, `programs.zsh`), carrying the PATH, git-identity unset, `ulimit -c 0` and `exec zsh` blocks and sourcing the session variables, so non-interactive shells find tools. The first switch backs up existing files once (`-b pre-nix`). The login shell stays POSIX (Coder). macOS: zsh, which macOS ships, is every account's login shell, so no login depends on the Nix store; an activation step sets it when it differs (including a shell left pointing into a removed store), and `setup.sh` resets a missing login shell before the switch. nix-darwin's `programs.zsh` puts the Nix profiles on PATH for every zsh; `zsh/.zshrc` (linked to `~/.zshrc`) carries the interactive setup and moves the Nix profiles back ahead of Homebrew's `brew shellenv`; on Linux home-manager's `~/.zshrc` sources the same file. fish was removed (owner's decision, 2026-10-18), and so was Ghostty, with no terminal declared in its place. The first account in the Mac's list is the primary account: it owns Nix's setup, Homebrew and the system settings, and `setup.sh` and the sync run only from it, so any other account can be removed. Rejected: `users.knownUsers` with `users.users.<name>.shell`, which makes nix-darwin manage the account itself. Flip: Coder rewrites those rc files on workspace start, in which case the Linux blocks move to `home.sessionVariables` plus a single sourced file. `~/.local/bin` goes after the Nix profile on PATH, so a binary an old installer left there (claude's) cannot shadow the declared one. Without systemd (containers, typical Coder workspaces) the installer can only set Nix up root-only (`--init none`), so `setup.sh` starts the daemon, and runs again after a restart.

12. **Verification.** (2026-10-17: herdr is commented out of the declaration with its steps and config link; Orion and mole are dropped.) (2026-10-18: herdr is removed from the setup: `herdr/`, its commented steps, the Claude hook and OpenCode plugin entry. The herdr items in decisions 7 and 8 no longer apply. The harness rules that name herdr leave with a separate change.) (2026-10-17: the macOS VM rehearsal is dropped; `verify/macos.sh` checks the configuration before a switch and the read-only `verify/macos-host.sh` asserts this Mac after it.) (2026-10-18: `setup.sh` replaces `macos.sh` and `linux.sh`, taking the platform from `uname` unless `--macos` or `--linux` forces it, so `curl ... | bash` and a plain `./setup.sh` need no arguments. The host checks move out of `verify/` into `sync.sh`, which runs the switch and then the checks on every real machine; `verify/linux.sh` provisions the container with `setup.sh` and checks it with `sync.sh`. On macOS, `sync.sh` from the primary account checks every listed account through sudo, each with its own clone's `sync.sh`. Rejected: a separate checks file sourced by `sync.sh`, which would keep two entry points for one step.) One self-contained script per check under `verify/` (host side and assertions together). Linux: `verify/linux.sh` keeps the Ubuntu base and becomes "install Nix with the same installer, then `home-manager switch` twice", replacing `nixos/nix` from the proto, so the check exercises the real install path. macOS fast loop: `verify/macos.sh` builds the darwin configuration without activating it (`nix build .#darwinConfigurations.<host>.system`) and evaluates the home links. macOS full: `verify/macos-vm.sh` runs `macos.sh` in a tart guest, twice, with `DARWIN_CONFIG=verify-vm`: the same modules for the base image's admin user, without App Store apps, since the guest has no App Store account. tart is the pinned upstream release, checked against its sha256 and kept in a cache, so the rehearsal needs nothing installed on the host and runs before Nix is. Without Nix on the host, `verify/macos.sh` also checks every macOS package against cache.nixos.org for availability and file collisions.

## Package coverage

The availability check ran against nixpkgs 8edc0c72e3 for aarch64-darwin: existence, `meta.available`, `meta.broken`, the homepage of every match (to catch same-name, different-program cases) and the presence of a prebuilt binary on cache.nixos.org. Results are in decision 4 and 5; every formula, mise tool and installer tool except the three Homebrew formulas is prebuilt, so no switch compiles from source. Items not declarable: the Safari web apps (Gmail, Calendar, Google Meet, created by Safari, routed by UUIDs Safari generates), Anarlog Dev (a local build), Claude Code URL Handler (created by Claude Code), Safari.

## Risks / Trade-offs

- [Casks that update themselves (1Password, Chrome, Slack, Zed) drift from the pinned version between switches] → accepted: Homebrew does not reinstall them while `greedy` is off; the pin governs fresh installs. This is the one place versions move outside the lock.
- [Superseded 2026-10-17: the owner installs App Store apps by hand and `masApps` is empty, its IDs kept as comments; firefox, libreoffice, notion and the search cask are dropped.] [App Store apps need an App Store sign-in, and `masApps` installs but never uninstalls] → the sign-in is listed as a manual step; removal of an App Store app is manual and named in the exceptions list.
- [nixpkgs lags fast-moving agent CLIs (codex, claude-code, opencode)] → decision 4 allows a pinned upstream flake input per tool; added only when the lag is observed, not preemptively.
- [Adopting /opt/homebrew could reinstall or remove packages on the first switch] → first host switch with `cleanup = "none"`, then a declared-versus-installed comparison, then `uninstall`.
- [home-manager owning Linux rc files overwrites hand edits on a box] → one backup per file on first switch; the flip condition in decision 11.
- [Flakes ignore untracked files, so a new module is silently absent from a build] → the verify scripts stage new files in their copy of the tree; the README states the rule.
- [macOS 27 is newer than the tart base image (Tahoe)] → the VM proves the configuration on the base image's macOS; the host switch is still gated and rollback-able.

## Migration Plan

1. Implement and pass the Linux container check (no host change).
2. Pass the macOS fast loop and the VM rehearsal.
3. Run `macos.sh` on this Mac (owner approval): it installs Nix and runs the first switch, with `cleanup = "none"`.
4. Compare the declared lists with `brew list`, `mas list` and `/Applications`; then switch with `cleanup = "uninstall"`.
5. Remove the old layer: links created by `lib/links.sh` that home-manager now owns are already replaced; delete `~/.local/share/mise`, `~/.config/mise`, the mise shims from PATH, `mise.toml`, `mise.lock`, `lib/links.sh`; reduce `macos.sh` and `linux.sh` to the Nix bootstrap and first switch.

Rollback: `darwin-rebuild switch --rollback` (or `home-manager generations` and activate the previous one) restores the previous generation. Until this change merges, `main` keeps the old scripts (`git switch main` restores them); the branch replaces macos.sh, linux.sh and lib/links.sh early because nothing on this Mac runs them between switches, while mise.toml, mise.lock, Mason and the fish PATH, which this Mac does use, stay until step 5. Full removal: `/nix/nix-installer uninstall`; nix-homebrew leaves /opt/homebrew in place.
